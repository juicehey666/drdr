# BRSET–mBRSET 图像预处理协议 v1

日期：2026-09-29  
适用任务：B2 单眼图像、B3 双眼图像、B4 双眼图像+表格及后续 Proposed 模型。

## 1. 设计原则

1. 原始文件只读，永不覆盖；
2. BRSET 和 mBRSET 使用同一套确定性预处理代码和参数；
3. 保留完整视网膜视场，不采用可能删除周边病灶的中心裁剪；
4. 离线预处理与训练增强严格分开；
5. validation、internal test 和 external test 只使用确定性变换；
6. 所有图像基线共享同一预处理版本，不能为某个模型单独挑选最有利的预处理；
7. 主分析不使用 CLAHE、Ben Graham 增强或血管增强，避免人为改变微小病灶与跨设备颜色差异。

## 2. 数据现状

已核查全部 JPEG 文件均可解码且为 RGB：

| 数据集 | 图像数 | 原始尺寸 |
|---|---:|---|
| BRSET | 16,266 | 2672×2056（5,586）；2984×2304（4,931）；2390×1880（3,650）；2420×1880（1,695）；951×874（403）；990×874（1） |
| mBRSET | 5,164 | 1600×1600（全部） |

两库的视场形状、黑边比例、颜色和相机特征不同。预处理应去除无信息外边框，但不能通过过强的颜色标准化“伪造”域泛化。

## 3. 主流程：`fundus_512_v1`

### 3.1 解码

1. 以 RGB 解码 JPEG；
2. 应用 EXIF orientation；
3. 记录原始宽高、文件大小和 SHA256；
4. 解码失败、通道数异常或尺寸异常时记录错误，不静默跳过。

### 3.2 视网膜有效区域检测

在缩小后的预览图上检测，减少开销：

1. 将图像最长边暂时缩放到 512；
2. 计算亮度 `Y = 0.299R + 0.587G + 0.114B`；
3. 初始前景为 `Y > 10/255`；
4. 对掩码执行小尺度闭运算并填洞；
5. 只保留包含图像中心的最大连通区域；若中心不属于任何区域，则取最大连通区域；
6. 取得前景外接框，并在四周扩张外接框宽高的 2%；
7. 将坐标映射回原图并裁剪。

阈值不是最终拍脑袋固定值：实现后须在 BRSET-Canon、BRSET-Nikon、mBRSET 各抽取至少 100 张图做覆盖层检查。如果固定阈值对某类相机失败，优先改为基于边缘/中心连通的自适应检测，但整个数据集仍必须使用统一算法。

### 3.3 安全回退

出现下列任一情况时不使用检测框，回退到原图：

- 有效区域面积小于原图的 30%；
- 外接框宽或高小于原图对应边的 50%；
- 外接框长宽比不在 `[0.75, 1.33]`；
- 检测框未覆盖图像中心；
- 预处理后肉眼抽查发现视盘、黄斑或视网膜圆周被切断。

所有回退均写入 `crop_fallback` 字段，后续分析其是否与数据集、相机或标签相关。

### 3.4 方形化与缩放

1. 对检测框做等边扩展，以较长边为方形边长；
2. 超出原图的部分用纯黑填充；
3. 使用 bicubic + antialias 缩放到 `512×512`；
4. 不进行额外中心裁剪；
5. 以高质量 JPEG（quality=95、无色度子采样）或 PNG 缓存。优先 JPEG 95 以控制磁盘空间，但必须通过原图与缓存图的视觉对照确认微小病灶没有可见损失。

建议缓存目录：

```text
data/processed/fundus_512_v1/
├── brset/
├── mbrset/
└── preprocessing_manifest.csv
```

缓存文件名保持原始 `image_id/file`，不得包含标签。

### 3.5 归一化

张量转换为 `[0,1]` 后，使用具体预训练骨干官方提供的 mean/std：

- ImageNet ConvNeXt-Tiny：使用 ImageNet mean/std；
- DINOv3、RETFoundGreen：使用各自官方 processor/config；
- 不从 BRSET+mBRSET 联合计算均值和标准差；
- 不使用逐图像 z-score 或 histogram matching。

离线缓存保存未经 mean/std 归一化的 RGB 图；归一化只在 dataloader 中完成，这样同一缓存可服务不同骨干。

## 4. 训练增强 `aug_moderate_v1`

只对 BRSET train 使用。每张图独立采样：

| 变换 | 参数 |
|---|---|
| HorizontalFlip | `p=0.5` |
| Affine | 旋转 `[-15°,15°]`、缩放 `[0.95,1.05]`、平移不超过 2.5%，`p=0.5` |
| ColorJitter | brightness/contrast/saturation `±0.10`、hue `±0.02`，`p=0.5` |
| Gamma | `[0.90,1.10]`，`p=0.2` |
| GaussianBlur | sigma `[0.1,1.0]`，`p=0.1` |

约束：

- 不使用 vertical flip；
- 不使用大角度旋转；
- 不使用 CutMix、MixUp、RandomErasing、强模糊或强色偏作为第一轮基线；
- 不使用会裁掉超过 5% 视场的 RandomResizedCrop；
- 左右眼和同眼不同视野可独立采样增强，因为它们本来就是独立采集；
- 增强参数必须对 B2/B3/B4 完全一致。

第一轮完成后可将 MixUp/CutMix 或更强设备增强作为独立实验，但不能与模型结构变化同时引入。

## 5. 验证与测试变换

BRSET validation、BRSET internal test 和完整 mBRSET external test 使用：

```text
RGB decode -> fundus crop -> square pad -> resize 512 -> tensor -> backbone normalization
```

- 无随机增强；
- 主结果不使用 test-time augmentation；
- 不根据 mBRSET 表现修改裁剪阈值、色彩或分辨率；
- 如果以后报告 TTA，必须作为次级结果，并同时保留无 TTA 主结果。

## 6. 左右眼与多视野规则

### 左右眼

- 离线阶段保持原始方向，不把某一眼强制水平翻转；
- 数据加载时按元数据明确输出 `left_images` 与 `right_images`；
- B2 对每眼独立预测，患者概率取两眼最大值；
- B3/B4 固定输入顺序为 `[left, right]`；
- 不允许用文件名或视盘位置猜测眼别替代标签字段。

### mBRSET 同眼多视野

- 每张图单独执行相同预处理；
- 第一轮基线对同眼全部视野的特征做均值池化；
- 不提前拼接图像，不把多视野当独立患者；
- 不按模型置信度挑选“最好的一张”，以免引入后验选择偏差。

## 7. 质量控制清单

`preprocessing_manifest.csv` 至少包含：

```text
dataset,image_id,patient_id,laterality,camera,
original_width,original_height,crop_x0,crop_y0,crop_x1,crop_y1,
foreground_fraction,crop_fallback,output_path,source_sha256,output_sha256
```

预处理完成后必须执行：

1. 确认输出数等于输入数；
2. 全量重新解码输出文件；
3. 检查输出均为 RGB、512×512；
4. 按数据集、相机、ICDR等级、质量标签分层抽样生成前后对照图；
5. 专门检查低照度、强伪影、严重PDR和视网膜圆周接近边缘的图像；
6. 统计 fallback 比例和前景比例，检测是否与相机或标签强相关；
7. 随机抽取至少 200 张人工检查，记录“完整视场、错误裁剪、明显色彩改变、病灶损失”。

通过标准：错误裁剪率应接近 0；只要发现视网膜有效区域被切断，就先修正算法，不能开始基线训练。

## 8. 预处理对照实验

论文主结果固定使用 `fundus_512_v1`。只需保留两个低成本对照：

- `P0 raw-resize`：原图直接 letterbox 到 512；用于判断去黑边是否必要；
- `P1 fundus_512_v1`：本文主流程。

可选敏感性分析：

- `P2 CLAHE/Ben-Graham`：仅在 B2 图像基线上比较一次。如果没有稳定改善，后续全部模型不再使用。

不能针对 BRSET 与 mBRSET 分别选择不同的最佳预处理，也不能以外部测试表现决定主流程。

## 9. 与基线任务的衔接顺序

1. 完成预处理脚本、manifest 和可视化 QC；
2. 用 P0/P1 各跑一个轻量 B2 单眼图像 smoke test；
3. 冻结 `fundus_512_v1`；
4. 完成正式 B2；
5. 在相同缓存和增强上完成 B3；
6. B4 只增加表格分支，不改变图像预处理；
7. Proposed 方法也沿用同一图像输入，使性能差异可以归因于融合方法。

## 10. 版本记录

正式运行前将以下内容写入 YAML 配置并纳入 Git：

- 预处理版本；
- 掩码阈值和形态学参数；
- 边框扩张比例；
- 输出尺寸和插值方法；
- JPEG/PNG编码参数；
- 增强概率与范围；
- 归一化配置；
- 源数据版本和 manifest SHA256。

任何参数变更均产生新版本，例如 `fundus_512_v2`，禁止覆盖已有缓存。
